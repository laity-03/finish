## 1. 范围与判定规则

本文只展开不是 STM32CubeMX 直接生成的项目代码：

- 手写或 Codex 修改的核心模块：`pid`、`motor`、`encoder`、`key`、`knob`、`mpu6050`、`ins`、`control`、`vofa`。
- 生成文件中的手写区：`Core/Src/main.c` 内所有实际有内容的 `USER CODE`。
- 工程接入改动：`CMakeLists.txt` 中新增手写源文件的部分。

## 2. 程序总链路

`TIM3` 每 1 ms 中断一次，`HAL_TIM_PeriodElapsedCallback()` 每累计 10 次把 `control_flag` 置位。主循环检测该标志后调用 `Control_Update()`：

`MPU6050 -> ins.c Mahony -> roll/pitch/yaw -> control.c 角度环 -> 目标 RPM -> encoder.c 反馈 RPM -> speed PID -> motor.c PWM -> TB6612 -> 电机`

同一主循环还用 UART1 发送 VOFA JustFloat 遥测，用 UART2 的阻塞刷新 OLED，并用 UART1 中断接收 VOFA 下调命令。按键、旋钮和 VOFA 命令都修改 `control.c` 的模式与目标值。

## 17. 关键结论与容易误解的点

- `main.c` 的 TIM3 回调只置标志，不在中断里跑 PID 和 OLED，因此耗时控制逻辑留在主循环。
- 控制周期标称 10 ms，但 PID 使用主循环实测 `dt`；若主循环被阻塞过久，`dt` 最大只按 50 ms 处理。
- 角度模式是串级控制：角度 PID 输出的是内层速度环目标 RPM，速度 PID 再输出 PWM。
- 速度模式直接绕过角度 PID，速度目标来自按键、旋钮切换前的状态或 VOFA 命令。
- 旋钮只用于角度目标，变化率限制为 90 度/秒，目标范围正负 75 度。
- MPU6050 在角度模式下掉线会强制停车；速度模式不依赖 MPU。
- `Control_GetTelemetry()` 的 `target_speed_rpm` 写的是内层速度环目标，不是所有模式下都等于用户最终设定的速度；VOFA 通道 4 因而展示的是内环实际目标。
- 代码中的实际角度死区是 `CONTROL_ANGLE_DEADBAND_DEG = 1.0f`，速度死区是 2 RPM；工程文档旧表格中写的 0.3 度和 1 RPM 与当前头文件不一致，应以后者为准。
- `oled.c/font.c` 是界面显示层和资源层，不参与电机闭环；OLED 刷新被限制到 5 Hz，减少 I2C 阻塞对控制实时性的影响。
- CubeMX 重新生成时，手写模块不会被覆盖；`main.c` 中只有 USER CODE 区会保留，因此新增初始化必须放在这些区域。
